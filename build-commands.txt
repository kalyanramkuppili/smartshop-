# KEY POINTS — REVIEWER Q&A
# ============================================================

# ── WHAT IS THIS APP? ────────────────────────────────────────
# smartSHOP is an AI-powered price comparison app for Indian
# e-commerce. A user types a product query (e.g. "headphones
# under 3000") and gets a ranked list showing the same product
# across Amazon, Flipkart, Croma, etc. with real-time prices,
# direct buy links, and user review summaries.


# ── HOW DOES THE SEARCH PIPELINE WORK? ──────────────────────
# Every search goes through a 3-stage pipeline:
#
#   Stage 1 — AI (Groq):
#     User query → Groq llama-3.1-8b-instant → JSON list of
#     4–6 products with names, categories, estimated prices,
#     store names, and review summaries. This is the "skeleton"
#     of the result.
#
#   Stage 2 — Enrichment (SerpAPI, runs in parallel with Stage 1):
#     For each AI product:
#       - Google Shopping search → real prices per store
#       - Google site: search    → direct product page URLs
#       - Amazon/Flipkart search engines → confirmed URLs + prices
#       - Google Images search  → real product thumbnail
#       - Google Reviews search → star rating, pros, cons
#
#   Stage 3 — Live Prices (ZenRows, mobile only):
#     Uses ZenRows to send a headless-browser / premium-proxy
#     request to the actual Amazon or Flipkart product page and
#     regex-scrapes the current selling price. This is the most
#     accurate price and overwrites all earlier estimates.
#     Has a 5-second timeout so it doesn't stall the UI.
#
# Price priority (highest → lowest):
#   ZenRows scraped > Direct store engine > Google Shopping > SerpAPI organic > Groq AI estimate


# ── WHY THREE DIFFERENT APIS? ────────────────────────────────
# Each API solves a different problem the others can't:
#
#   Groq    → Natural language understanding. It interprets
#             vague queries ("good laptop for college") and
#             knows which products exist, their specs, and which
#             stores carry them. But its prices are estimates.
#
#   SerpAPI → Real-time Google data. It finds direct product
#             page URLs, actual listed prices, and real images.
#             But it can't scrape behind paywalls or bot-blocks.
#
#   ZenRows → Bypasses bot-detection. Amazon and Flipkart block
#             regular HTTP requests — ZenRows uses residential
#             proxies and headless Chromium to get through and
#             read the live price from the actual product page.


# ── WHY IS SERP API DISABLED ON WEB? ────────────────────────
# Browsers enforce CORS (Cross-Origin Resource Sharing).
# SerpAPI and ZenRows do not return CORS headers, so calling
# them directly from a browser tab throws a network error.
# The app detects Platform.OS === 'web' and skips those calls,
# falling back to Groq AI estimates + Unsplash images.
# On Android (APK), there is no CORS restriction — all 3 APIs
# work fully.


# ── HOW DOES BUDGET FILTERING WORK? ─────────────────────────
# extractBudget() parses the user's query with regex patterns:
#   "under 30000"  →  budget = 30000
#   "below ₹50,000" → budget = 50000
#   "iPhone 15 Pro Max 256GB" → no budget (256 < 1000 and no ₹)
#
# The budget is enforced at THREE checkpoints:
#   1. In the Groq prompt — AI is told not to suggest products above budget
#   2. Post-Groq filter  — removes any product the AI returned above budget
#   3. Final filter      — removes stores/products where ZenRows/SerpAPI
#                          confirmed a real price above budget


# ── HOW ARE IMAGES RESOLVED? ────────────────────────────────
# Image resolution has 4 fallback layers (best to worst):
#   1. SerpAPI thumbnail from a matched Google Shopping result
#   2. SerpAPI Google Images search result for the product name
#   3. Pre-validated Unsplash URL matched by product keyword
#      (e.g. "headphone" → headphone photo, "fridge" → fridge photo)
#   4. Category-level Unsplash fallback (e.g. "Audio" → headphones)
# This ensures no product card ever shows a broken image.


# ── HOW ARE URLS VALIDATED? ─────────────────────────────────
# serpApiService.ts has a SEARCH_PAGE_PATTERNS array of regexes
# that detect search/category pages (e.g. /search, /category/,
# /s?, /browse/) and reject them. A store entry is only kept
# in the final result if its URL points to an actual product
# page, not a listings page.
# Note: /\?q=/ was intentionally removed from this list — it
# was too broad and was rejecting valid product URLs that
# happen to contain ?q= tracking parameters.


# ── WHAT HAPPENS IF AN API FAILS? ────────────────────────────
# Every external call is wrapped in try/catch or .catch():
#   - Groq fails       → throws error, app shows "offline data" toast
#   - SerpAPI fails    → caught per-call; Groq data is used as fallback
#   - ZenRows times out (5s) → AI/SerpAPI price is used instead
#   - SerpAPI exhausted → 429 error caught; app falls back gracefully
# The app never fully crashes — it always shows something.
